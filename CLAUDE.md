## Projeto
**BoomListener** (nome único do app, no ícone e em todo texto; vem de *sonic boom* + ouvinte, e o Android não aceita "!" nem vírgula no nome): reprodutor de música **local** para Android, em Material 3 Expressive, com edição de tags, página de artista (Deezer + Last.fm) e radar de lançamentos dos artistas seguidos. Gratuito, sem anúncios, sem conta. Público: **global** (pública desde a 0.36.2; deixou de se chamar beta em 30/10/2026).
- Nome nos arquivos: `boomlistener` (`boomlistener_vX.Y.Z.apk`; título da Release: "BoomListener vX.Y.Z").

## Stack
- Stack: Kotlin 2.4 + Jetpack Compose (Material 3 Expressive) + Media3. AGP 9.4, Gradle 9.6, `compileSdk 37`, `targetSdk 36`, `minSdk 26`, Java 17 (o Gradle roda com JDK 21).
- Build: `./gradlew assembleRelease` · Testes: `./gradlew testDebugUnitTest`. **Nada do Gradle compila nesta sessão** (repositórios Maven fora da rede liberada): a única prova é o CI.
- Mapa (módulos Gradle): core → `core/*` · data → `data/*` · features → `feature/*` (no singular, decisão do mantenedor) · entrada → `app`.
- Versão: `APP_VERSION` em `gradle.properties` (`versionCode = MAJOR*10000 + MINOR*100 + PATCH`; nunca editar `versionCode`/`versionName` direto).
- Versionamento: SemVer, **regra e não escolha**: o número sai do `[Unreleased]`, calculado pelo Claude. Só correções (Fixed, Security) → PATCH; algo novo ou alterado compatível (Added, Changed, Deprecated) → MINOR; algo que quebra compatibilidade (Removed, mudança incompatível) → MAJOR. Known issues sozinho não gera versão. Número pedido fora da regra: explicar o certo e esperar a confirmação com ele. Trocar o sistema de versionamento só com pedido explícito.
- Release: commit de release na main (APP_VERSION novo + seção no CHANGELOG, sem tag ainda) → `.github/workflows/ci.yml` cria a tag `vX.Y.Z` e publica `boomlistener_vX.Y.Z.apk` na Release do GitHub. Build para vistoria: artefato `boomlistener_vX.Y.Z-build<nº da execução>` de cada push (o APK dentro tem o mesmo nome).
- Pacote: `com.boomlistener.app`, fixo para sempre · R8 ativo no release, nunca desligar (com `-dontobfuscate`: os nomes ficam legíveis nos erros, decisão do mantenedor; problema só no release → regra `-keep` em `app/proguard-rules.pro`).
- Ícone: `app/src/main/res/mipmap-anydpi*/` e `drawable/ic_launcher_*`; só muda se o mantenedor pedir.

## Arquitetura
Módulos Gradle com dependências só em uma direção: `app → feature → data → core`. Implementações de `data` são `internal` (o resto só vê a interface `…Repository`). Detalhes, mapa dos módulos e comportamentos em [`ARCHITECTURE.md`](ARCHITECTURE.md).

## Regras de estrutura
- Feature não importa outra feature; o compartilhado sobe para core/data. Navegação entre features passa pelo `app`.
- Banco, APIs e arquivos só via data. Core sem regra de negócio.
- Código novo vai para o módulo da responsabilidade dele. Sem módulo adequado, **perguntar antes** de criar um ou de usar um "quase certo".
- Dependência nova só em `gradle/libs.versions.toml` (nunca versão escrita num `build.gradle.kts`), e só justificada. Antes de usar versão nova, conferir na documentação oficial que ela existe e o que exige.
- Configuração repetida entre módulos vai para os plugins de `build-logic/`. AGP 9 tem Kotlin embutido: nunca aplicar `org.jetbrains.kotlin.android` num módulo; `kapt` não funciona (KSP).
- Dados da pessoa ficam em DataStore e arquivos (sem Room). Mudança no formato do que já está guardado **sempre** com migração escrita e testada; nunca apagar dados para "começar limpo". Arquivo novo de dados da pessoa entra no backup (`USER_DIRS` do `BackupEngine`).

## Limites do app (não mudam)
- **Nunca reproduz** conteúdo de serviços externos. Fontes externas são só informação e links "abrir em…". Compartilhar manda o link de **busca** do YouTube Music; o banner manda imagem ou vídeo com **no máximo 30 s** da música, nunca a música inteira. Nada de API do YouTube, da API interna do YouTube Music, Piped/Invidious ou Bandcamp.
- **Sem nada de social** (decisão de 0.33.0): sem amigos, "ouvindo agora", recomendações, reações nem servidor. O perfil é só da pessoa e só no aparelho.
- **Permissões:** só áudio (`READ_MEDIA_AUDIO`; `READ_EXTERNAL_STORAGE` até o 12; `WRITE_EXTERNAL_STORAGE` só no 8 e 9), `MANAGE_MEDIA` (25/11/2026, pedido do mantenedor: acesso especial opcional no Android 12+, liberado pela pessoa em Ajustes → Biblioteca; só tira a caixa de confirmação do sistema ao **apagar** músicas, e sem ele tudo continua como antes; gravar tags ainda pergunta, pois exigiria também `ACCESS_MEDIA_LOCATION`: não pedir sem decisão do mantenedor), `POST_NOTIFICATIONS` só para avisos de lançamentos e para o aviso de fim de ano do Wrapped (que **nunca pede a permissão**: só sai se ela já foi concedida; sem ela, cartão no Perfil). **Nunca** fotos/vídeos (imagens pelo Photo Picker), `BLUETOOTH_CONNECT`, `RECORD_AUDIO` (nada da API `Visualizer`) ou Cast. No Android 10+ gravar tags é por `MediaStore.createWriteRequest`.
- **Modo offline:** todo `openConnection` novo chama `OfflineMode.requireOnline()` antes; só a verificação de atualizações passa.
- Identidade visual própria: inspiração de layout pode, copiar marca ou visual de outro app não.

## Design (Material 3 Expressive)
- Nenhuma cor, fonte ou forma "na mão" numa tela: `MaterialTheme.colorScheme`, `.typography`, `.shapes`, `.motionScheme`. Valores próprios só em `core/designsystem`. Cores em par com o "on" correspondente.
- Componentes do `androidx.compose.material3`; componente próprio só sem equivalente, em `core/designsystem`. APIs experimentais só dentro de `core/designsystem`, embrulhadas.
- Edge-to-edge, temas claro, escuro e AMOLED, cor dinâmica no Android 12+.
- Todo movimento usa `boomSpatialSpec`/`boomFastSpatialSpec`/`boomEffectsSpec`/`boomScreenSpec` (nada de `tween(300)` à mão). Única exceção: a animação do ícone em Sobre (`BoomLogo`, core/designsystem), coreografia de marca com tempos próprios (decisão de 15/11/2026). Tela/painel novo tem transição e "voltar" que fecha só ele; tela nova da navegação usa `BoomNavScreen`. Painéis de baixo sempre `BoomModalSheet`.
- **Cores dos ícones dos Ajustes (regra, 19/11/2026):** o círculo do ícone usa `BoomAccent` (famílias fixas em `core/designsystem`: Blue, Green, Red, Orange, Yellow, Purple, Pink, Teal, Neutral; não seguem a cor dinâmica). Itens da mesma categoria usam a mesma família (Aparência = Purple, Reprodução = Blue, Biblioteca = Green, Compartilhamento = Orange, Sistema = Teal, Sobre = Pink); itens de assuntos diferentes (ex.: no Sobre: bug = Red, privacidade = Green) usam famílias próprias. Ícone novo em Ajustes sempre com `accent` explícito, nunca cor na mão.
- **Barra de busca (regra, 19/11/2026):** toda busca do app usa `BoomSearchField`, que perde o foco quando o teclado fecha (sem cursor piscando com o teclado fechado) e também com um toque fora dele (toque, não deslize; `clearSearchFocusOnTapOutside`, aplicado na raiz do `BoomListenerApp` e dentro do `BoomModalSheet`, que é outra janela); o "X" só apaga o texto e mantém o foco. Busca nova não cria campo próprio.
- Toda opção dos Ajustes mora numa categoria (Aparência, Reprodução, Biblioteca, Compartilhamento, Sistema). Se nenhuma serve, perguntar. A tela inicial de Ajustes só tem essas cinco categorias e o Sobre (que é informação, não opção): nada de item solto lá (verificar atualizações e avisos de atualização ficam em Sistema → Atualizações).

- **Layout próprio de tela larga** (barra lateral, painel do artista, player deitado; removido em 30/10/2026): tablet usa o layout do retrato e o celular fica em pé.
